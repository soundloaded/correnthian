# Web v1 Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the `create-next-app` default in `apps/web` with a working dual-rail wallet foundation: session, portfolio read, and honest refusal states for both buy paths.

**Architecture:** Next.js App Router (Server Components for shell/marketing, Client Components only where state or browser APIs are needed), TanStack Query against `@correnthian/api-client` types, disclosures rendered verbatim from `packages/assets`, no key material anywhere near the web app.

**Tech Stack:** Next.js 16.3.8, React 19.2.8, Tailwind v4, `@correnthian/ui` shadcn components, `next/font` Geist (already configured in scaffold layout).

**Spec:** `docs/superpowers/specs/2026-10-23-dual-rail-web-v1-design.md` — the plan argues from the spec, so the spec travels with it; executors read both

## Global Constraints

- Key boundary holds: `packages/wallet-core` takes no HTTP client, no RPC endpoint, and no provider SDK.
- Disclosures rendered verbatim, disclosed before signature. Never recompute `describeBacking()` output in a screen.
- Asset identity is `(chain, contract, issuer)` — never key a map, cache, balance record, or URL parameter on `symbol`.
- No number that is not in code. No fee numbers, custody terms, provider names written without verification.
- No own gold token, no Correnthian custody, no principal risk.
- Provider-agnostic adapters, disabled by default. Anything unexecutable renders honest unavailability, never a fake rate.
- AGENTS.md banner in `apps/web/AGENTS.md` and `apps/web/CLAUDE.md` must be committed with work (regenerated by `next dev`; removing it from a diff re-creates the change).

## Review Focus

- A session token stored where any script on the origin can read it, and the app rendering trusted HTML from the API — expect XSS-hardened rendering (verbatim disclosure strings only, no `dangerouslySetInnerHTML`) and expiry enforced on read, not just by timer.
- A portfolio number that mixes surrogate and domain `assetId` — expect an exact-id join, and a holding that reads as unpriced at zero must say so rather than show `$0` as a price.
- A quote that names a size it cannot fill — expect `executionQuality` and `sizeCapUsd` rendered as constraints, and `'none'` rendering no buy button at all.
- An unexecutable buy path that invents a rate — expect the refusal copy from the API (`providerUnavailable`) surfaced verbatim, never a plausible-looking number.
- A screen that names a concrete rail (`dex`/`provider` literal) — expect registry capability resolution instead; a literal rail name in a screen or service is a bug.
